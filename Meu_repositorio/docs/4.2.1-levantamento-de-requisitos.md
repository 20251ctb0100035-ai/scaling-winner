# 4.2.1 Levantamento de Requisitos

## Como os requisitos foram levantados

Os requisitos do DoceAgenda foram levantados em três passos. Primeiro, uma **entrevista** com Mariana, confeiteira e cliente do sistema, sobre como as encomendas funcionam. Depois, uma **conversa curta** com um cliente frequente, para ouvir o lado de quem encomenda. Por fim, a **análise de um documento**: o caderninho em que Mariana anota os pedidos.

O que está entre aspas na tabela a seguir foi dito por eles. A coluna da necessidade é interpretação minha, lida de volta para Mariana antes de virar requisito.

❓ **A confirmar com a cliente:** Mariana não informou o prazo de entrega. Adotei sete dias para seguir com a análise.

## Da fala à necessidade

| # | Fala | O que é | Necessidade por trás |
| --- | --- | --- | --- |
| F1 | "Eu queria um sistema com uma telinha bonita mostrando os produtos do cardápio" (Mariana) | solução | o cliente saber se o produto está disponível sem perguntar |
| F2 | "Todo dia alguém vem perguntar se tal produto está disponível" (Mariana) | necessidade | consulta de disponibilidade pelo cliente |
| F3 | "Anoto a encomenda num caderninho e às vezes esqueço a data" (Mariana) | necessidade | registro com data de entrega calculada pelo sistema |
| F4 | "Encomenda que fica para trás eu só descubro quando o cliente vem cobrar" (Mariana) | **necessidade implícita**: ela não pediu, reclamou | acompanhar a situação das encomendas |

## Histórias de usuário

| # | História de usuário | Veio de |
| --- | --- | --- |
| HU01 | Como **cliente**, quero **consultar a disponibilidade de um produto**, para **saber se posso encomendá-lo sem perguntar à confeiteira**. | F1, F2 |
| HU02 | Como **cliente**, quero **receber meu pedido**, para **não ficar com uma encomenda pendente**. | F3 |
| HU03 | Como **confeiteira**, quero **registrar uma encomenda**, para **saber quem pediu cada produto**. | F3, F4 |
| HU04 | Como **confeiteira**, quero **cadastrar um produto novo**, para **que ele possa ser encontrado no sistema**. | F4 |
| HU05 | Como **confeiteira**, quero **ver as encomendas atrasadas**, para **organizar as entregas pendentes**. | F3 |

## Requisitos funcionais

| # | Nome | Requisito | Veio de |
| --- | --- | --- | --- |
| RF01 | Cadastrar produto | O sistema deve permitir que a confeiteira cadastre um produto no cardápio. | HU04 |
| RF02 | Cadastrar cliente | O sistema deve permitir que a confeiteira cadastre um cliente. | regra da confeitaria |
| RF03 | Consultar disponibilidade | O sistema deve permitir que o cliente consulte a disponibilidade de um produto. | HU01 |
| RF04 | Registrar entrega | O sistema deve permitir que a confeiteira registre a entrega de uma encomenda. | HU02 |
| RF05 | Registrar encomenda | O sistema deve permitir que a confeiteira registre uma encomenda para um cliente. | HU03 |
| RF06 | Listar atrasados | O sistema deve listar as encomendas vencidas e ainda não entregues. | HU05 |
| RF07 | Calcular data de entrega | O sistema deve calcular a data de entrega ao registrar a encomenda. | F3 e o escopo da 4.1 |

## Requisitos não funcionais

| # | Categoria | Requisito | Veio de |
| --- | --- | --- | --- |
| RNF01 | desempenho | A consulta deve responder em menos de 3 segundos. | características da 4.1 |
| RNF02 | acesso | Somente confeiteiras identificadas podem alterar o cardápio e as encomendas. | características da 4.1 |
| RNF03 | dispositivo | O sistema deve funcionar no navegador, no computador do balcão e no celular do cliente, sem instalação. | características da 4.1 |

## Conferência com a 4.1

| Item do escopo (4.1) | Requisitos |
| --- | --- |
| O sistema cadastra produtos e clientes. | RF01, RF02 |
| O sistema mostra a disponibilidade ao cliente. | RF03 |
| O sistema registra encomendas e calcula a data de entrega. | RF05, RF07 |
| O sistema registra a entrega. | RF04 |
| O sistema lista encomendas atrasadas. | RF06 |

**Toda história tem requisito.** HU01 virou RF03, HU02 RF04, HU03 RF05, HU04 RF01 e HU05 RF06.

**Todo requisito tem origem.** O RF02 veio de uma regra da confeitaria, e o RF07 veio da fala F3 e do escopo.

**O que a conferência mudou.** A lista inicial tinha cinco requisitos funcionais. A conferência com a 4.1 mostrou que faltavam o requisito para encomendas atrasadas e o cálculo da data de entrega. Entraram RF06 e RF07. A seção fecha com sete requisitos funcionais e três não funcionais, dentro do teto.
